# Shake-to-Feedback and Desktop Enablement — Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tester can shake an Android phone or iPad to open the feedback composer, labelled with the tab they were on, and the feedback entry becomes available on iOS, macOS and Windows (not Linux).

**Architecture:** Platform availability is one predicate; shake detection is a pure threshold/cooldown class fed by `sensors_plus` through an injectable stream provider, mounted once in `_AppShell`; the sheet gains a `screen` label so shaked reports carry the current tab instead of `Settings`.

**Tech Stack:** Flutter, Riverpod, `sensors_plus`, Firestore rules, FlutterFire CLI.

**Spec:** `docs/superpowers/specs/2026-11-08-feedback-capture-design.md` (the shake addition is specified in this plan and recorded back into that doc).

## Global Constraints

- Shake is native Android and iOS only, never web, and is inert while a route is already on top of the shell.
- `platform` values sent to Firestore become exactly `web`, `android`, `ios`, `macos`, `windows` (lowercase), and `firestore.rules` must accept that set — `Linux` is not a supported platform and keeps no entry point.
- macOS gets `com.apple.security.network.client` in both entitlement files.
- Nothing initializes Firebase at app startup; the shake path only opens the sheet.
- No analytics, no crash reporting, no persistent identifier.
- `dart format` only on touched files (`dart format lib test` drifts on 52 unrelated files in this repo).
- Every task ends with `flutter analyze`, the task's tests, and the task's build verification.

## Review Focus

1. **A shake while playing.** Strumming, tapping or a train must not fire the sheet: three consecutive samples above threshold, a 1.5 s cooldown, and no fire while a route is open.
2. **Shake on a platform that cannot shake.** Web and desktop must construct no sensor subscription at all.
3. **A shaked report carries the right screen.** Shaking on Roll must submit `screen: 'roll'`, not `Settings`.
4. **Rules accept the new platform values but nothing else.** A direct write with `platform: 'linux'` or `platform: 'iOS'` is denied.
5. **Desktop builds still start without a network.** macOS/Windows launch with the feedback entry present and no Firebase initialization until the sheet opens.

### Task 2: Shake detector

**Files:**
- Create: `lib/utils/shake_feedback_detector.dart`
- Test: `test/utils/shake_feedback_detector_test.dart`

**Interfaces:**
- Consumes: nothing.
- Produces: `class ShakeFeedbackDetector { ShakeFeedbackDetector({double threshold = 2.6, int requiredSamples = 3, Duration cooldown = const Duration(milliseconds: 1500)}); bool add(double x, double y, double z, DateTime at); void reset(); }` where `add` returns `true` exactly when a shake fires.

- [ ] **Step 1: Write the failing test**

```dart
// 2.6 g threshold, 3 confirming samples, 1.5 s cooldown.
test('fires after three confirming samples, not before', () {
  final d = ShakeFeedbackDetector();
  final t = DateTime(2026, 11, 8, 12);
  expect(d.add(0, 0, 9.81, t), isFalse);
  expect(d.add(30, 0, 0, t.add(const Duration(milliseconds: 16))), isFalse);
  expect(d.add(30, 0, 0, t.add(const Duration(milliseconds: 32))), isFalse);
  expect(d.add(30, 0, 0, t.add(const Duration(milliseconds: 48))), isTrue);
});

test('a quiet sample breaks the run', () {
  final d = ShakeFeedbackDetector();
  final t = DateTime(2026, 11, 8, 12);
  d.add(30, 0, 0, t);
  d.add(0, 0, 9.81, t.add(const Duration(milliseconds: 16)));
  d.add(30, 0, 0, t.add(const Duration(milliseconds: 32)));
  d.add(30, 0, 0, t.add(const Duration(milliseconds: 48)));
  expect(d.add(30, 0, 0, t.add(const Duration(milliseconds: 64))), isFalse);
});

test('cooldown swallows the tail of one shake', () {
  final d = ShakeFeedbackDetector();
  final t = DateTime(2026, 11, 8, 12);
  for (var i = 0; i < 3; i++) {
    d.add(30, 0, 0, t.add(Duration(milliseconds: 16 * i)));
  }
  expect(d.add(30, 0, 0, t.add(const Duration(milliseconds: 64))), isFalse);
  expect(d.add(30, 0, 0, t.add(const Duration(milliseconds: 80))), isFalse);
});
```

- [ ] **Step 2: Run it and see it fail**

Run: `flutter test test/utils/shake_feedback_detector_test.dart`
Expected: FAIL — the class does not exist.

- [ ] **Step 3: Implement**

Magnitude is `sqrt(x² + y² + z²) / 9.80665`; a sample counts when it is at least `threshold`. `requiredSamples` consecutive counting samples fire once, record the time, and reset the run; any quiet sample resets the run. A fire inside `cooldown` of the previous fire is suppressed and resets the run.

- [ ] **Step 4: Run the test**

Expected: PASS.
